# workbench

个人工作台，目前提供 AI 模块。复用仓库 httpserver、httpclient、webui、kv 和 assetstore，页面和静态资源编译进一个 Go 二进制，无前端构建步骤或运行时 SDK。

## 构建与运行

在仓库根目录使用 Go 1.24 或更高版本：

```sh
go build -o ./bin/workbench ./cmd/workbench
./bin/workbench -addr 127.0.0.1:8090 -data-dir ./workbench-data
```

打开 `http://127.0.0.1:8090`。所有相对路径基于启动程序时的工作目录，换目录运行时建议使用绝对 `-data-dir`。

| 参数/环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `-addr` | `127.0.0.1:8090` | HTTP 监听地址 |
| `-data-dir` | `./workbench-data` | 配置、会话、任务、资产与日志目录 |
| `WORKBENCH_PASSWORD` | 空 | 可选访问密码；非回环监听时必需，用户名固定为 `workbench` |

跨机器访问可使用 SSH 本地端口转发，保持服务监听回环地址；也可设置密码并监听 `0.0.0.0:8090` 供可信网络访问。原生 HTTP 服务不自行配置 TLS，同源检查不信任转发头，不能直接置于终止 TLS 的反向代理后。未设密码的本地模式仅接受 `localhost`/回环 IP 的 Host。

## 导航与首次设置

AI 导航层级是「工作台 → AI → 服务商 → profile → 子功能」，提供 OpenAI、Anthropic、Google Gemini、xAI 和通用 AI 五个入口。「资产库」与「后台任务」放在全局工作区，不属于某个服务商。

1. 进入服务商的「管理 profiles」，新建 profile，填写名称、API key、base URL 和 proxy URL。
2. 进入文字或其他功能页，在顶部切换 profile。每家可以保存多组凭据。
3. 直接填写实际模型名，或点击「发现模型」在弹窗中搜索并选择。打开弹窗只展示常用模型和当前标签页的缓存；点击「刷新模型」才请求服务商目录，首次没有缓存时也不自动请求。
4. 调整当前服务商的原生参数，先「预览请求」，再发送。

模型、会话、云端资源、资产、任务和日志列表统一使用当前标签页缓存；进入页面或打开选择器不自动刷新，无缓存时提示手动读取。刷新、分页和重试才读取列表，操作完成不会额外重拉列表。模型与云端资源缓存另绑定配置版本，修改 key、地址等配置后失效。

官方 base URL 默认值：OpenAI 为 `https://api.openai.com/v1`，Anthropic 为 `https://api.anthropic.com/v1`，Gemini 为 `https://generativelanguage.googleapis.com`，xAI 为 `https://api.x.ai/v1`。Gemini 的版本路径由工作台添加。通用 AI 用于 OpenAI 兼容中转站，手填 API 前缀，并显式启用站点支持的图片、音频和资源能力。

API key 保存在本机配置文件，浏览器不会读到已保存的明文；编辑留空保留原 key，清空需勾选明确选项。复制 profile 不复制 key。Profile 在弹窗内编辑，保存期间锁定输入；发生版本冲突时可载入最新配置并保留当前输入，再提交。

proxy URL 留空使用环境代理，`-` 表示直连，支持 http/https/socks5/socks5h。模型发现、生成、资源上传下载都使用提交时的 profile 配置；每次原生 API 请求上限 10 分钟，生成结果的媒体入库阶段另有 2 分钟总时限。

## 独立功能页

| 入口 | 独立工作页面 |
| --- | --- |
| OpenAI | 文字（Responses / Chat）、图片生成、图片编辑、语音合成、音频转写、音频翻译、文件、容器、Batch |
| Anthropic | 文字 Messages、文件、Message Batches |
| Gemini | 文字、图片生成、图片编辑、语音合成、音频转写、视频任务、文件、Batch |
| xAI | 文字（Responses / Chat）、图片生成、图片编辑、语音合成、音频转写、视频任务、文件、Batch |
| 通用 AI | 文字（Responses / Chat），以及 profile 明确启用的兼容功能 |

参数面板随服务商及功能变化，包含对应的 service tier、采样、推理、输出和工具设置；具体模型支持哪些参数由上游校验。当前未提供 Live/Realtime、客户端工具自动执行或多候选回复选择，完整限制见 [上下文回传](DEVELOPMENT.md#上下文回传)。

页面以输入和结果为主，宽屏把展开的参数放在旁边，窄屏放在输入区之后；参数按生成、系统指令和工具分组。切换 Chat Completions 后，Responses 专用工具和文件引用会停用。通用 AI 切换 profile 时，若目标未启用当前功能，会进入文字页。

「原生扩展参数」接受 JSON 对象，保留 false、0 和厂商字段；与表单已生成字段重名时报错，避免静默覆盖。

## 请求预览与文字会话

「预览请求」在弹窗中展示实际 HTTP 方法、URL、body 和上传文件说明，复用发送时的请求构造逻辑，不调用上游、不创建会话。长字符串仅在预览中折叠，可以展开、复制或下载完整 body；实际发送不截断。multipart 预览展示字段和文件元信息，不读取整份附件；Gemini 文件上传展示启动和传输两个阶段。Esc 关闭后回到原操作按钮，再次预览使用当前输入。

弹窗支持「复制 curl」，导出完整 Bash 4+ 脚本。按脚本注释设置 `API_KEY`，自定义代理另设 `PROXY_URL`，上传另设 `FILE_1` 等绝对文件路径；已保存的 key 和代理凭据不会导出。multipart 需要 curl 7.81+，长字段还需 `mktemp` / `rm`；Gemini 上传另需 `wc`。无法无损导出时显示原因；浏览器拒绝剪贴板访问时提供手动复制弹窗。

文字会话按 profile 和协议隔离，在当前标签页记住会话和续接点；点击「刷新会话」读取列表。页面只展示当前分支，默认使用所选续接点的祖先路径构造请求；「从这里继续」选择续接点，发送后形成分支，「复制为新会话」保留该路径及归属。「管理」支持重命名和删除本地会话。完整原生输出和流式事件保存在会话中，可展开检查。

历史以左右分开的消息气泡展示，用户在右、模型在左。正文默认展开，每条消息可以单独收起；收起时保留文字摘要和完整的媒体占位图。图片、音频和原生 JSON 按需展开，避免打开旧会话时立即解码全部媒体或排版大段 JSON。折叠只影响显示，不裁剪保存内容或请求上下文。历史与输入区共用紧凑面板，长对话在历史区统一滚动；手动向上阅读时，流式更新不把视图拉回底部。

同模型续接保留各家协议所需的推理、工具和媒体结构；更换模型时保留用户普通输入、附件和助手可见文本。中止或失败的助手结果仅回传已有可见文字。显式使用 Responses 的 `previous_response_id` / `conversation` 时由服务端管理历史，不再叠加本地分支。协议细节和官方依据见 [上下文回传](DEVELOPMENT.md#上下文回传)。

Enter 换行，Ctrl / ⌘ + Enter 发送，回复可直接复制。同一会话只能同时生成一个回答，活动任务期间禁止删除会话。

## 后台任务与生成历史

生成页把文字、图片、语音、转写及视频提交/查询交给 Go 服务独立执行。收到任务确认后，切页、刷新、关闭浏览器或前端电脑断网不会取消任务；运行 Go 服务的机器仍需在线，不能随前端一起休眠。原页面保留文字流式显示；重新打开尚未完成的会话时显示「正在后台生成中」，点击「刷新状态」读取结果，不重接或重放事件流。

发起非流式请求的页面会读取当前任务详情直到完成；重新打开的页面只恢复当前任务并提供手动刷新。这是当前任务的进度查询，不会刷新历史列表。全局「后台任务」可按 profile、功能、状态筛选持久化记录，独立生成页的「生成历史」直达对应筛选。任务详情可查看结果、打开所属会话或停止任务；删除已结束的任务记录保留资产和会话。

「停止」取消 Go 服务中的任务，停止或失败时保留已收到的文字和输入草稿。它不会取消已提交到服务商的视频或 Batch 任务。视频仍由用户手动查询，取得完成结果后才下载媒体入库。资源上传、删除及 Batch 管理操作仍随当前 HTTP 请求执行，云端 Batch 状态从各家的资源页查询。

## 全局资产库

资产库统一保存本地上传、生成图片、对话中的图片工具结果、音频和已下载视频等媒体，以及通过资源页上传/下载的文件。图片可预览下载，音频和视频可播放；Gemini PCM 音频包装为 WAV。每份资产记录名称、类型、大小、时间和来源，与当前 profile 无关。

1. 在「资产库」上传资源，或等待生成结果自动入库。
2. 在管理表中预览、下载、重命名、删除，以及标记或取消「精选」。新资源默认不精选。
3. 聊天选图片、图片编辑选原图/蒙版、音频转写选音频、云端文件上传选文件，都使用同一个精选选择器。打开只读缓存，点击「刷新精选」才读取最新列表；需要新增资源时可打开管理页，再回来刷新。

调用页提交资产 ID，由服务端读取内容并构造各家的原生请求，不把本机资产先下载到浏览器再上传。发送和预览都检查资源是否仍存在且已精选。资源一旦进入已保存的会话，请求中的原生附件会保留；后来取消精选或删除库中的文件不改写历史上下文，也不清理原始请求日志。

「导入旧会话媒体」只导入已保存会话输出中的内联媒体，跳过正在生成的会话及已有资产引用的消息，重复点击不会重复导入。它不请求远端 URL；以前仅显示在临时页面、未保存的结果不能恢复。

已识别的生成结果 URL 会下载到本机，下载失败会保留原生结果并报告错误，不重新生成。只处理服务商定义的图片/视频结果字段，不抓取正文链接或工具参数中的任意 URL。外部媒体下载不携带 profile 凭据，Gemini 生成文件通过同源原生文件接口鉴权下载。源站、代理及服务商本身需要由用户信任。

## 文件、容器与 Batch

文件、容器和 Batch 按 profile 缓存当前页及分页游标，容器文件还按容器隔离。表格展示文件名、ID、大小、状态、时间和行内操作，支持当前页搜索；资源详情在弹窗中查看，可按 Esc 关闭。

- 文件：从精选资产上传、详情、复制引用、删除和支持的下载。Gemini 用户上传文件 API 不提供内容下载，页面不显示此操作；生成的视频和 Batch 结果可以下载。
- 容器：创建、详情、删除，进入容器查看文件；支持上传、引用已有文件 ID、下载和删除。
- Batch：创建、查询详情、取消和结果下载。OpenAI 使用 purpose=batch 的 JSONL 文件；Anthropic 使用原生请求数组；Gemini 使用模型与输入文件；xAI 支持上传输入文件或创建空任务后追加 batch_requests，结果分页读取。

上传和创建使用弹窗，可先预览请求；完成后提示手动刷新列表。删除和取消的确认弹窗会等待请求结束，失败后保留上下文供重试。创建 Batch 的文件候选需点击「刷新文件」，xAI 结果弹窗需点击「刷新结果」。分页失败保留当前列表；文件及 JSONL 结果下载保留原始字节。页面不自动翻页、重复提交或清理云端资源。

本地 API 接收的 JSON 原生操作请求上限 64 MiB（包含 Gemini 内联媒体），文字会话请求上限 4 MiB；后者不包含服务端追加的历史。每次资产上传和 multipart 总计限制 300 MiB；一次最多选择 20 份资产，需转为原生内联附件时总计不超过 32 MiB。multipart 文件超过 8 MiB 内存额度时使用临时文件，后台任务持有独立文件副本，结束后清理。服务商自身的大小和格式限制仍适用。缓冲响应和收集的流式事件累计上限默认 256 MiB；二进制响应通过临时文件下载。

## 日志与存储

每次原生 API 请求都开启请求记录（生成结果中的外部媒体文件下载不单独写原生 HTTP 日志）。响应正文默认不记录，可在全局设置中开启；本地 API 支持按次覆盖。关闭时仍保留状态、字节数等 response metadata。聊天回复仍作为会话内容保存，与原始 HTTP 响应日志是两回事。

日志支持按 profile 和操作筛选，在详情弹窗中查看时间、状态、request/response metadata 和正文；单个正文预览最多 256 KiB，截断时可下载完整记录。认证头和签名 URL 元信息脱敏，正文原样保留，包含提示词和上传文件。HTTP EOF 标志不表示模型完成；操作状态和会话错误应一并查看。日志写入失败会阻止请求或返回失败，不能据此认为服务端未执行并直接重试。

```text
workbench-data/
  config.json                 # 独立 config KV：profiles、key、日志默认值
  sessions/<session-id>.json   # 会话 KV：节点、分支、原生输出、任务与资产引用
  tasks/<task-id>.json         # 任务 KV：状态、结果、错误、来源与资产引用
  assets/<asset-id>/
    metadata.json             # 名称、类型、精选与来源 KV
    content                   # 原始文件字节
  logs/<operation-id>/
    context.json              # 操作归属、时间与结果
    <request-id>/
      request.json
      request.body
      response.json
      response.body           # 仅开启响应日志时创建
  .lock/                      # 进程持有的排他目录锁
```

修改一个会话只保存它自己的 KV，不保存其他会话或 config。修改先保存成功再发布到内存，KV 使用同目录临时文件替换，不提供断电 fsync 保证。进程内支持并发，数据目录只能由一个进程使用。目录权限 0700、新写文件 0600；不要把数据目录纳入 Git 或静态网站。

正常退出先停止接收新任务，取消正在生成的后台任务，再关闭连接并等待活动处理和保存完成。重启将仍未完成的任务标为「已中断」，不自动重试或重新计费。异常终止后若 `.lock/` 留存，先确认没有运行实例，再删除这个锁目录。备份/跨机搬迁应先停止程序，复制整个数据目录；旧日志由用户按需离线归档。

## 测试

全仓 Go 检查按 [开发约定](../../AGENTS.md#完成改动前) 执行，页面改动还需运行下面的 JS 和浏览器测试。协议测试使用本地假服务，不需要真实 key；尚未使用真实账号逐项联调。

```sh
node --test utils/webui/request_test.cjs
WORKBENCH_GO=go WORKBENCH_CHROMIUM=/usr/bin/chromium \
  node --test cmd/workbench/browser_test.cjs
```

浏览器测试自行构建并启动临时工作台和假服务，无需预先启动应用。复用已安装的 Node、Playwright 和 Chromium；工具准备、成功判定和清理遵循 [webui 流程](../../utils/webui/README.md#开发与测试流程)。`WORKBENCH_GO` / `WORKBENCH_CHROMIUM` 指定已有可执行文件；动态库、Playwright 包和字体分别可用 `WORKBENCH_BROWSER_LIBS`、`NODE_PATH`、`FONTCONFIG_FILE` 指定。

浏览器覆盖五个入口的全部功能页在桌面和手机下的布局，以及模型选择、profile 冲突恢复、历史与折叠、会话分支、流式失败、预览与复制、资源分页、下载原文、弹窗和日志。四种主题均检查显示和键盘操作，并验证首屏样式加载。还覆盖后台断连续跑、停止、结果恢复、精选复用与延迟请求隔离。截图写入已忽略的 `bin/workbench-browser/`。

代码职责和内部请求约定见 [开发说明](DEVELOPMENT.md)。
